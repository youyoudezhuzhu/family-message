# 产品模型更正：家庭留言 = 群聊

> 2026-09-25 辉哥明确。**这是模型更正，不是加功能** —— 之前的"设备间投递"理解是错的。

---

## 一句话

**一条消息发进一个共享空间，所有设备都能看到，空间里完全以昵称区分谁说的。**

---

## 去掉什么

| 去掉的 | 说明 |
|---|---|
| ❌ 「发送给」设备选择器 | 发送时不再选目标。网页端和 PC 端现在都过分强调了这一步 |
| ❌ 设备间投递语义 | 不是"从某设备发送到某设备" |
| ❌ 逐设备的 已发送/已送达/已显示 状态 | **完全去掉**。消息只有一个状态：**已发送** |

## 保留什么

| 保留的 | 说明 |
|---|---|
| ✅ **昵称是唯一的区分** | 谁说的，靠昵称。昵称仍纯本地、不上传服务端 |
| ✅ **所有已注册设备都收到并显示** | 真正的群聊，设备就是"群成员" |
| ✅ **设备页完整保留** | 截图 / 远程关机 / 远程解锁 / 在线状态 |
| ✅ **设备页只在 NAS 网页端显示** | 网页端是**全功能版本**；PC 端不展示设备管理 |

---

## 各层怎么改

### 服务端

- `POST /api/messages` 请求体变为 `{sender_name, content, message_type?}`
  - `targets` 字段**保留但忽略**（向后兼容老客户端），服务端**自动广播给所有已注册设备**
- 消息对象对外只暴露**单一状态** `status = "sent"`
  - `message_targets` 表**保留**（投递记账、离线补投还要用），但**不再对外暴露逐设备状态**
  - 这是最省风险的改法：数据结构不动，只是不展示
- `GET /api/messages` 就是**群聊流**（全部消息按时间）
- 推给 PC 的 `message` 帧：广播给**所有已连接设备**，但**排除发起者自己**
  （自己发的消息不该弹自己的窗）
- 状态上报（ack / popup_displayed）链路**保留**，只是 UI 不展示了

### 网页端（全功能版本）

- **发送区**：只留 昵称 + 内容 + 发送。删掉「发送给」和快捷设备网格
- **消息记录**：一条统一的群聊流（昵称 + 内容 + 时间 + 已发送）
- **设备页**：完整保留
- 昵称机制不变（纯本地 localStorage）

### PC 端（群聊客户端）

- **全屏弹窗**：收到群聊消息时弹出（排除自己发的），保留回复 + 知道了
- **客户端窗口**：群聊视图 —— 消息流 + 回复栏，回复直接进群聊
- **不展示设备页 / 设备管理**
- **去掉客户端窗口的「控制台」入口**（设备页只在网页端）
  - 托盘菜单里本机运维的入口（设置 / 日志 / 配置目录 / 退出）保留

---

## 不变的部分（别顺手改了）

- 昵称纯本地，服务端只存 `sender_name` 字符串
- 设备注册、WebSocket、心跳、重连、离线补投
- 截图 / 关机 / 会话状态 / 开机自启 / 远程解锁链路
- 米家控制、审计、权限
